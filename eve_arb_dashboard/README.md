## 계산하는 4가지 패턴

패턴 이름은 두 번째 허브 자리에 붙습니다 (아마 `X` = 고른 허브).

| 패턴 | 사서 파는 곳 | 운송 |
|---|---|---|
| **A** | X의 **매도창**에서 사서 → Jita **매수창**에 팔기 | O |
| **B** | Jita의 **매도창**에서 사서 → X **매수창**에 팔기 | O |
| **C** | X의 **매도창**에서 사서 → Jita **매도창**에 팔기 | O |
| **D** | Jita의 **매도창**에서 사서 → X **매도창**에 팔기 | O |

> **C/D는 예전 것과 다릅니다.** 예전 C/D는 한 스테이션 안에서 매수호가가 매도호가를
> 뒤집는(사자 > 팔기) 경우만 센 탓에 표가 늘 비어 있었습니다.
> 이제는 **두 허브의 매도창을 맞물게** 돕니다 — 한쪽 매도호가에 사서 다른 쪽 매도창에 파는
> 차익이고, 화물을 싣고 가니 네 패턴 모두 부피·ISK/m³가 유효합니다.

후보는 두 허브 주문판에서 네 갈퀴(A/B/C/D) 조마진 금액이 나는 종목 + 한 스테이션에서 사자 > 팔기가 뒤집힌 종목까지 함께 담습니다.

## 화면 구성 (탭)

패턴 넷을 탭으로 가른다. 라벨은 고른 짝을 받아 한 짝이면 그 이름을 쓴다 (여러면 `허브`).

| 탭 | 어떤 것을 세는가 | 파는 곳이 매수창이라 판매 브로커 수수료가 **없다** |
|---|---|---|
| 🅰 `허브→Jita · 매수창에 판매` | 허브 매도창에서 사서 **Jita 매수창**에 파넘김 | 예 |
| 🅱 `Jita→허브 · 매수창에 판매` | Jita 매도창에서 사서 **허브 매수창**에 파넘김 | 예 |
| 🅲 `허브→Jita · 매도↔매도` | 허브 매도창에서 사서 **Jita 매도창에 포개어** 팔기 | 아님 — 4% 무조건 |
| 🅳 `Jita→허브 · 매도↔매도` | Jita 매도창에서 실어서 **허브 매도창에 포개어** 팔기 | 아님 — 4% 무조건 |

그 뒤로 `🃀 네 패턴 통합` · `📊 페어 비교` · `🔬 종목 상세`가 따른다. 각 판이 내는 표의 기본 정순은 아래 네 자리다.

## 표 읽기

| 항목 | 설명 |
|---|---|
| 매집가 / 청산가 | 창가가 아니라, 체결순서로 계산한 평균 체결가 |
| 조마진% / 순이익% | 브로커 수수료 · 판매세를 뺀 뒤의 것 |
| 체결량 | 한계이익이 0 이 되기 전에 채워진 최대 수량 |
| 묶인 자본 | 그 체결량이 드는 돈(ISK) — 예산한도로 걸러라 |
| 총부피 m³ / ISK/m³ | 운송에 필요한 자릿과 자릿 대비 효율 |
| 필요 운항 / 1회 운항 이익 | 사이드바의 "1회 적재 가능 부피" 기준 |
| 셀오더 총량 | 팔 허브에 포개져 있는 매도주문 전 물량 |
| 10일 거래량 | 그 종목의 하루 평균 거래량 (최근 열흘 새 평균, ESI history) |
| **셀오더/거래량** | 위 둘을 나눈 값 — **작을수록 좋다** |
| ○○호가 유지 h | 그 가격이 시장에서 버틴 시간 — 오래 버틴 게 진짜다 |

### 표 정렬 순서
`arb_core.rank_key`가 네 항목을 순서대로 재고, 표와 `arb_list.py`가 같은 순서를 쓴다.

1. **순이익** — 클수록 앞 (ISK)
2. **묶인 돈** — 작을수록 (`capital`)
3. **부피** — 작을수록 (`volume_m3`, 모르면 맨 뒤)
4. **셀오더/거래량** — 작을수록 (`sell_queue_days` = 팔 허브 매도잔 총량 ÷ 하루 평균 거래량)

넷째 자리는 파는 쪽 허브의 매도주문 총량을 그 종목의 하루 평균 거래량(ESI 최근 열흘 평균)으로 나눈 값입니다. 이 값이 작으면 그 자리에 이름을 올려도 팔릴 차례가 금 옵니다. 거래량이 없는 종목은 값을 비우고 표에서 맨 뒤로 갑니다. 사이드바의 「셀오더/거래량 걸림(일)」로 걸러 낼 수 있습니다. 예전 정렬(ISK/m³ 우선)은 사이드바 「표 정렬」에서 바꿉니다.

 순이익은 값이 커서 두 줄이 완전히 같기가 어렵습니다. 그래서 2, 3, 4가 잘 안 동작합니다. 이 문을 열려면 「순이익 같은 걸로 보는 간격 (%)」을 줍니다. 10%를 주면 순이익은 10% 안까지 같은 것으로 보고, 그 다음에 묶인 돈, 부피, 셀오더/거래량 순으로 가립니다.

C/D 는 두 허브의 매도창이 엇갈려야 납니다 — 한쪽 매도호가보다 다른 쪽 매도호가가 더 비싸야 합니다.
두 창에 물려 있는 주문만 세므로 물량은 얇을 수 있습니다. 창에 없는 가격에 주문을 걸고 버티는 일은 세지
않습니다. 체결 창은 늘 얇은 쪽을 따라 잡힙니다.

수수료는 기본/실무 프리셋 결과를 겹쳐서 보여주고, 필요하면 직접 입력합니다.
판매 비용은 **판매세**와 **브로커 수수료**로 분리했습니다. 확인해 보니 (EVE Uni Wiki, 2026-08):
브로커 수수료는 **'immediate'가 아닌 지정가를 걸 때만** 부과됩니다 — 즉시판매엔 없습니다.
대신 판매세는 방식(즉시/지정)과 무조건 붙고, 2025-03 패치부터 기본 **7.5%** (Accounting Lv5면 3.4%).
사이드바의 「판매 창을 즉시판매로 가정」이 켜진 상태에서는 판매세만 부과되고,
끄면(지정가 가정) 브로커 수수료가 더해집니다.

**단, C/D는 예외입니다.** C/D는 파는 편이 태생부터 **매도 지정가**(내 매도호가를 창에 걸어서 그 창과 맞서 파는 것)이므로
브로커 수수료가 무조건 있다. 그래서 판매세와 따로 세습니다 — 기본 **4%**고, 사이드바 「C/D 매도 브로커 수수료 %」
또는 `--broker-cd`로 고칩니다. A/B(매수창에 바로 파넘기는 길)에는 달지 않는다.

## 통합에서 만진 곳

* `esi.py` — 네 허브를 `HUBS`에 모으고 `SECONDARIES = ["Amarr", "Dodixie", "Rens"]`, 진행 줄용 `region_pages()`
* `arb_core.py` — `patterns_for(hub_b)` 가 짝마다 라벨을 만들고, `analyze_type(..., hub_b=)` 가 행에 `pair`/`hub`를 심는다.
  C/D는 `match_sell_ladder(살 매도창, 팔 매도창, …)` — 매도창끼리 맞물게 돌린다. `candidate_scores` 도 네 갈퀴를 돈다.
  `pair_summary(rows)` 가 탭용으로 쌍을 세며 A~D를 다 센다.
* `arb_list.py` — 화면 없이 C/D만 CSV로 적어내는 실행부 (`--hubs`·`--only`·`--listing`·`--max-net-pct`)
* `app.py` — `run_scan(hubs, ...)` 이 Jita를 한 번 받고 짝만큼 받는다 · 후보를 쌍별로 모은다 · `쌍` 컬럼 · `📊 페어 비교` 탭
* `test_arb_core.py` — 매도↔매도 계산기와 네 패턴 행, 후보 점수가 네 갈퀴 기는지 본다
* `test_app_data.py` — 세 쌍이 한 표에 섞여 뜨는지, 라벨에 허브 이름이 박히는지 본다

### 🚫 낚시물 차단

악성 판매자가 파는 척만 걸어둔 물건은 표에 오르기도 전 걸러진다. 목록은 두 데서 온다:

- **`blocklist.json`** (이 폴더, 깃에 있음) — 다시 켜도 그대로. `ids`는 타입 id, `names`는 아이템 이름(대소문자 무시).
- **사이바 「🚫 낚시물 차단」 칸** — 이번 판에만 그 자리에서 id나 이름을 쉼터로 친다.

사이바의 **⬇ blocklist.json 받아라**로 지금 것을 받아서 이 폴더에 그걸 뒤집어씌우면(커밋하면)
그게 기준이 된다. 클라우드의 임시 저장은 재배포에 맞아 제자리를 잊으니, 오래 둘 물건은 반드시
깃으로. 예:

```json
{ "ids": [11288], "names": ["Unstable Worm Protein"] }
```
